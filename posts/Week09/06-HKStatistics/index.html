Example - Getting Statistics on Data

For some values, like steps, you want to get a total number over a given time period to give you a sense of how close you are to completing your goal, however you don't want to keep repeating an ever growing query. You really only need what's changed since the last time you queries. Luckily the HKQueryAnchor class helps with that. Let's start by adding a steps property to HealthKitDataHelper

//add at the top of the class
@Published var steps: Double = 0.0

Then make the getTodaysSteps function:

//Query to ready today's steps
  func getTodaysSteps() async throws -> Double {

Define the type we want to use by using the .stepCount identifier

  let stepsQuantityType = HKQuantityType.quantityType(forIdentifier: .stepCount)!

Then define a HKQueryAnchor. Set it to nil here, which will force the app to query everything. If you passed in an existing anchor here, the query would only return the data stored since that anchor was used.

     var anchor: HKQueryAnchor? = nil

Build a predicate to get the steps for today, using Date() to grab the current date/time, and the Calendar.current.startOfDay function to get the start of the current day.

  let now = Date()
  let startOfDay = Calendar.current.startOfDay(for: now)
  let predicate = HKQuery.predicateForSamples(withStart: startOfDay, end: now, options: .strictStartDate)

Then lets build the query:

     let anchorDescriptor = HKAnchoredObjectQueryDescriptor(predicates: [.quantitySample(type: stepsQuantityType, predicate: predicate)], anchor: anchor)

    let results = try await anchorDescriptor.result(for: HKHealthStore())
    anchor = results.newAnchor
    return results.addedSamples.reduce(0.0) { $0 + ($1.quantity.doubleValue(for: HKUnit.count())) }

The anchorDescriptor is similar to the query descriptor used in our historical data function, but takes in the anchor to help define when to start looking for data. That descriptor is used to fetch the data via result(for: HKHealthStore), which uses async/await and may throw. We can set the anchor to the one returned by the result, and grab our quantity to return using the results.addedSample function, which returns the samples that have been added since the anchor was last used. Some functional programming via reduce sums up our value so it can be returned to the caller.

To be able to view this in the simulator, add the following to the Form in our view

HStack {
  Text("Steps")
  Spacer()
  Text("\(numberFormatter.string(from: NSNumber(value: hkData.steps))!)")
}

And don't forget to add a call to loadData:

   func loadData() async throws {

    readBirthDay()

    try await readWeight()

    self.steps = try await getTodaysSteps()
  }

Run this in the simulator. Initially, the app will show the value currently in the HK Store, and if we go to the Health app and add new values, and then return to our app, nothing happens! We need some way to tell the view to refresh itself when returning to the foreground. Luckily, Notification center sends notices out when apps enter the foreground, so let's attach the following modifier onto the Form in our view:

.onReceive(NotificationCenter.default.publisher(for: UIApplication.willEnterForegroundNotification)) { _ in
  self.hkData.loadData()
}

This will call loadData again when the app enters the foreground. Add new step values into the Health app again, and bounce back to the app via the home buttons - you'll see that a new summed value is displayed, as you would expect.
